### **Introduction**

Title: GRPO Sanity Check, Model Quantization, and Autoware PR Plan

This seminar provides a two-week progress update covering three parallel workstreams. First, we report results from the GRPO sanity check on Diffusion-Planner, identifying the need for fine-grained evaluation metrics. Second, we outline our TensorRT quantization plan using NVIDIA's DL4AGX toolkit for real-vehicle deployment. **Section 1: GRPO Sanity Check for Fine-Tuning**

Before committing to full GRPO training on Diffusion-Planner, we conducted a sanity check to verify pipeline feasibility. GRPO eliminates the Value Model used in PPO and instead samples multiple outputs per query, computing advantages through relative comparison within the group. The sanity check runs 10 iterations to confirm whether results converge to either 100% failure or success, validating that the reward signal and training pipeline function correctly.

The result was mixed: overall metrics such as collision rate and compliance rate were successfully evaluated. However, fine-grained metrics like lateral error and curvature error are not provided by the current evaluation framework, making it difficult to pinpoint which specific behaviors to target for RL improvement. The evaluation methodology will therefore be redesigned to include these detailed metrics before proceeding with full training.

**Section 2: Model Quantization with DL4AGX**

To address the FPS bottleneck in the RAVEE project for real-vehicle E2E deployment, we plan to quantize both GenAD and Diffusion-Planner to TensorRT using NVIDIA's DL4AGX toolkit. Since VAD-TensorRT is already supported within DL4AGX and GenAD shares a similar architecture with VAD, quantization is expected to be feasible with manageable engineering effort. This work directly targets the inference speed requirements for on-vehicle deployment.

**Section 3: Autoware Pull Request Plan**

While we were focused on other tasks, significant updates have been made to the Autoware platform. Our plan is to port the existing VAD + RuleBased hybrid code to the latest Autoware version, refactor it into a clean HLC-based (High-Level Command) package, and submit an official Pull Request to the Autoware repository. This contribution would make E2E planning accessible as a first-class module within the Autoware ecosystem.
